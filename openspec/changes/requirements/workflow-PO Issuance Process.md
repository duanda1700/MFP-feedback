- - # 采购订单下发流程设计文档

    ## 1. 流程基本信息
  
    - 流程名称：采购订单下发流程
  
      
  
    - 流程目的：将采购订单任务逐一下发给供应商，确保订单能够及时执行，通过 TRAE 系统实现订单下发的标准化、可视化管理
  
      
  
    - 适用范围：采购订单外发模块中状态为 "待下发" 和 "有变更" 的订单（**仅支持逐一下发，无批量下发功能**）
  
      
  
    - 流程负责人：采购管理团队
  
      
  
    - 技术落地框架：TRAE CN 智能编程平台
  
      
  
    - 核心技术栈：
  
      前端：Vue 3 + TypeScript + Vue-Vben-Admin（组件库 / 布局 / 权限）
  
      后端：Node.js + TypeScript（接口开发 / 事务 / 集成）
  
      数据库：MySQL 8.0（数据存储）
  
      流程引擎：Camunda 7.24（流程编排 / 任务执行）
  
      
  
    ## 2. 流程参与者
  
    - 发起者：采购订单外发模块操作人（采购专员 / 采购主管），**仅可对单条订单执行下发操作**
    - 供应商：接收并执行任务的外部合作方（通过系统通知 / 邮件获取订单信息）
    - 系统：MFP-Feedback 系统、TRAE 系统（核心操作载体）

    ## 4. 详细流程步骤
  
    ### 4.1 触发条件
  
    - 用户在 TRAE 开发的采购订单列表页面，筛选出状态为 "待下发" 或 "有变更" 的订单；
    - 仅支持**逐条操作**：点击单条订单右侧的「下发」按钮（无批量下发按钮，TRAE 前端不渲染批量操作控件）；
    - 权限校验：TRAE 前端先校验用户操作权限，无权限时「下发」按钮置灰并提示。
  
    ### 4.2 步骤 1：跳转至订单下发流程编辑页面
  
    - TRAE 前端实现逻辑：
  
      
  
      1. 点击「下发」按钮后，前端通过路由跳转至独立的订单下发编辑页面（路径示例：`/purchase/order/issue/{orderId}`）；
  
         
  
      2. 页面加载时，通过 URL 中的 `orderId` 调用后端接口，拉取该订单的完整基础信息；
  
         
  
      3. 页面布局（TRAE 前端组件化开发）：
  
         
  
         - 顶部：页面标题「采购订单下发 - 订单编号 XXX」+ 返回按钮（返回订单列表）；
         - 左侧：订单基础信息展示区（只读），包含订单编号、采购物料、数量、创建时间、原关联供应商等；
         - 右侧：下发信息编辑区（可编辑），包含供应商选择、下发说明、计划完成时间；
         - 底部：提交下发按钮 + 取消按钮（取消后返回列表）。
  
         
  
      
  
    ### 4.3 步骤 2：页面自动填充基础信息
  
    - 订单基础信息：从 TRAE 数据库的「采购订单表」中读取，以只读形式展示（不可修改）；
    - 供应商字段：默认回显该订单关联的供应商（从 TRAE 「供应商表」读取可用供应商数据），支持下拉选择更换；
    - 下发说明、计划完成时间：初始为空，标注「必填」标识，聚焦编辑区引导用户填写。
  
    ### 4.4 步骤 3：用户填写下发信息（编辑页面核心操作）
  
    - 拉取采购订单及采购订单明细表：
  
      拉取当前订单对应的采购订单及采购订单明细数据形成列表，支持对采购订单明细列表中关键物料属性、制造符合性检查物料属性的更改与标记（仅针对当前订单，无批量处理逻辑）。
  
      
  
    - 计划反馈模板生成：
  
      生成生产计划反馈模板：提供 “生成模板 “按钮，基于当前采购订单及下属明细数据，同步生成计划反馈模板，计划反馈模板条目与采购订单明细一一对应，同时支持新增行项目（仅针对当前订单）。
  
      
  
    - 供应商选择：
  
      
  
      - TRAE 前端渲染下拉选择框，数据源为后端返回的「可用供应商列表」（过滤禁用状态供应商）；
      - 支持模糊搜索供应商名称 / 编码，默认选中订单原关联供应商，允许手动更换；
      - 选择后实时显示供应商联系人、联系方式等辅助信息，便于用户核对。
  
      
  
    - 下发说明：
  
      
  
      - 输入控件：TRAE 内置的多行文本框，字数限制 0-500 字；
      - 验证规则：非空校验，失去焦点时实时校验，为空时显示红色提示「下发说明不能为空」。
  
      
  
    - 计划完成时间：
  
      
  
      - 输入控件：TRAE 日期时间选择器，限制选择当前时间之后的日期；
      - 验证规则：选择时间需在当前时间 + 90 天内，超出范围实时提示「计划完成时间不能超过 90 天」。
  
      
  
    ### 4.5 步骤 4：提交下发请求（TRAE 前后端交互）
  
    1. 前端校验：用户点击「提交下发」按钮后，TRAE 前端对所有必填字段做最终校验，校验失败则定位至错误字段并提示；
  
       
  
    2. 后端处理（事务化执行，仅针对单条订单）：
  
       
  
       - 前端通过 TRAE 请求工具提交参数（orderId、supplierId、下发说明、计划完成时间）至后端接口；
       - 后端校验订单当前状态（防止并发操作导致状态异常），仅处理「待下发 / 有变更」状态的订单；
       - 创建下发任务记录：在「采购订单下发任务表」插入单条数据，关联订单 ID 和供应商 ID；
       - 更新订单表：将当前订单状态改为「已下发」，记录更新人、更新时间；
       - 事务控制：所有操作封装在数据库事务中，任意步骤失败则回滚，确保数据一致性。
  
       
  
    ### 4.6 步骤 5：下发结果反馈
  
    - 成功场景：
  
      
  
      - 后端返回成功结果后，TRAE 前端跳转回订单列表页面，顶部显示「订单 XXX 下发成功」的提示（TRAE 内置提示组件）；
      - 订单列表中该订单状态更新为「已下发」，操作日志同步生成（仅记录当前订单操作）。
  
      
  
    - 失败场景：
  
      
  
      - 后端返回失败结果（如订单状态已变更、供应商不可用），编辑页面保留用户已填写的所有内容，顶部显示具体失败提示；
      - 提供「重新提交」按钮，用户修正问题后可直接重新提交，无需重新填写。

### 5.2 输入数据（接口入参）

| 参数名           | 类型               | 必传 | 说明                                   |
| :--------------- | :----------------- | :--- | :------------------------------------- |
| orderId          | Number             | 是   | 单条订单的 ID（编辑页面从 URL 中获取） |
| supplierId       | Number             | 是   | 目标供应商 ID（编辑页面选择后传入）    |
| issueDesc        | String             | 是   | 下发说明（多行文本）                   |
| planCompleteTime | String（ISO 格式） | 是   | 计划完成时间，如 "2026-04-30 18:00:00" |

### 5.3 输出数据（接口出参）

| 参数名  | 类型   | 说明                                 |
| :------ | :----- | :----------------------------------- |
| code    | Number | 结果码（200 = 成功，其他 = 失败）    |
| message | String | 结果描述                             |
| data    | Object | 成功数据（包含 taskId、orderStatus） |

## 6. 异常处理（TRAE 开发适配）

| 异常类型     | 触发场景                               | 处理方案（TRAE 实现）                                        |
| :----------- | :------------------------------------- | :----------------------------------------------------------- |
| 网络异常     | 编辑页面提交请求时网络中断 / 超时      | 1. TRAE 前端设置 30 秒请求超时；2. 显示「网络异常，请检查网络后重试」提示；3. 保留用户已填写的所有内容，不跳转页面；4. 提供「重新提交」按钮，点击后重新发起请求 |
| 数据验证失败 | 下发说明为空、计划完成时间超出范围     | 1. 前端实时校验，提交前拦截；2. 错误字段标红，显示具体提示（如「计划完成时间不能超过 90 天」）；3. 提交按钮置灰，仅当所有校验通过后可点击 |
| 权限不足     | 无订单下发权限的用户点击「下发」按钮   | 1. 前端隐藏「下发」按钮；2. 若通过 URL 直接访问编辑页面，后端返回 403，前端跳转至无权限提示页 |
| 供应商不可用 | 选择禁用状态供应商 / 供应商已删除      | 1. 前端下拉框过滤禁用供应商，无法选择；2. 后端二次校验，返回「供应商 XXX 已禁用，请重新选择」提示；3. 编辑页面保留其他填写内容，聚焦供应商选择框 |
| 订单状态异常 | 下发时订单已被其他用户处理（状态变更） | 1. 后端校验订单当前状态，返回「订单 XXX 状态已变更，下发失败」；2. 编辑页面显示失败提示，提供「返回列表」按钮；3. 跳转回列表后，订单状态自动刷新为最新状态 |
