# MFP-Feedback 系统设计规范

## 项目基本信息

项目名称：MFP-Feedback System

项目类型：制造计划回传系统

项目目标：采集发动机零部件制造过程数据，及时掌握订单制造进度，实现交付风险预警；追踪关键零部件制造状态，涵盖工序计划、制造符合性检查进展，确保过程可控，可追溯。

前端：Vue 3 + TypeScript + Vue-Vben-Admin

后端：Nest.js + TypeScript

数据库：MySQL 8.0

流程引擎：Camunda 7.24

项目根目录：f:\mfback\MFP-feedback

## 产品概述

### 产品背景
为及时掌握零部件试制过程进展，应对研制阶段采购延误风险，提升对供应商端制造现场掌握情况，同时，对适航取证过程制造符合性检查环节进行控制。设计并开发制造计划回传系统。

### 产品价值
1. 统一管理：平台集中分发研制订单及订单条目，各供应商合规获取，统一收集和管理各类反馈信息。
2. 高效处理：自动化流程和状态跟踪，提高供应商反馈处理效率
3. 数据驱动：通过数据分析，发现延期交付风险与改进机会

## 新增需求

- 集成层：ERP 系统 API 和 Camunda 7.24 工作流引擎

#### 场景：模块划分
给定系统架构
当设计模块划分时
则系统应包括：
- 前端模块：认证模块、仪表盘模块、采购订单模块、生产计划模块、进度反馈模块、任务管理模块、预警管理模块、用户角色模块
- 后端模块：认证模块、订单模块、计划模块、反馈模块、权限模块、预警模块、数据分析模块、集成模块

#### 场景：数据流设计
给定系统架构
当设计数据流时
则：
- ERP 系统 → 后端集成模块 → 订单模块 → 数据库
- 后端订单模块 → 前端采购订单模块
- 前端生产计划模块 → 后端计划模块 → 数据库
- 前端进度反馈模块 → 后端反馈模块 → 数据库
- 后端预警模块 → 前端预警管理模块
- 后端数据分析模块 → 前端仪表盘模块

### PD2: 前端组件设计

#### 场景：详细页面设计
给定前端需求
当设计页面时
则系统应包括：

- 仪表盘（首页）：核心统计指标、异常预警、待办任务汇总、关键物料进度可视化图表
- 采购订单管理页面：ERP 同步的采购订单列表、订单查询、筛选、关键物料标记、任务下发操作
- 承制订单详情页面：订单明细穿透式查看、订单全生命周期状态展示
- 生产计划编制页面：在线编辑、Excel 导入、计划校验、提交审批、计划编制进度展示
- 进度反馈填报页面：双列表展示承制订单与计划明细、责任人/状态/备注编辑与提交
- 个人代办中心页面：待处理任务展示、筛选、一键跳转操作、流程节点可视化
- 供应商代办中心页面：供应商待处理任务展示、关键件/制造符合性检查任务标红、优先级筛选
- 角色权限配置页面：角色定义、权限粒度配置、数据级权限分配
- 系统设置页面：阈值配置、规则引擎配置、系统参数设置
- 数据监控看板页面：多维度统计、可视化图表、自定义时间范围、报表导出
- 预警处理页面：预警任务处理、结果记录、闭环时间记录、关联采购主管与供应商负责人

#### 场景：前端技术实现
给定前端需求
当设计技术实现时
则：
- 框架复用：基于 Vue-Vben-Admin 开箱即用的组件，减少重复开发；扩展业务组件（如双列表反馈组件、预警标记组件、进度可视化组件）
- 状态管理：使用 Pinia 管理全局状态，按模块划分 store（如订单 Store、计划 Store、权限 Store、预警 Store），确保状态统一与响应式更新
- API 请求：封装 Axios 请求拦截器，统一处理 JWT 令牌校验、请求头设置、错误捕获（如网络异常、接口 401/403/500）；响应拦截器统一格式化返回数据，区分业务错误与系统错误
- 表单验证：基于 VeeValidate / Element Plus 表单验证规则，封装通用验证方法（如物料图号格式、日期范围、数量正整数），支持自定义校验提示
- 数据可视化：集成 ECharts 实现仪表盘、订单统计、交付率、预警趋势等图表，支持图表联动、下钻、导出图片/Excel
- 文件处理：使用 xlsx 库处理 Excel 导入/导出，支持批量导入时的错误详情导出（标注错误行与原因）
- 响应式适配：基于 Vue-Vben-Admin 的适配方案，支持 PC 端不同分辨率（1366×768 及以上），关键页面适配平板端
- 缓存策略：本地缓存用户权限、常用筛选条件、最近访问页面，减少接口请求；敏感数据（如令牌）存储在 sessionStorage，关闭标签页自动清除

### PD3: 后端服务设计

#### 场景：API 接口设计
给定后端需求
当设计 API 时
则：
- 认证模块：登录、登出、刷新令牌、获取用户信息
- 订单模块：获取订单列表、获取订单详情、标记关键物料、下发任务、同步 ERP 数据
- 计划模块：获取计划列表、获取计划详情、创建计划、更新计划、导入计划、提交审批
- 反馈模块：获取反馈列表、获取反馈详情、提交反馈、更新反馈状态
- 权限模块：获取角色列表、获取权限列表、创建/更新角色、分配权限
- 预警模块：获取预警列表、获取预警详情、处理预警、更新预警状态
- 数据分析模块：获取统计数据、获取趋势数据、导出报表
- 集成模块：同步 ERP 数据、触发 Camunda 工作流

#### 场景：详细业务流程实现
给定后端需求
当设计业务流程时
则：
- 采购订单下达与任务分发流程：ERP 数据同步 → 订单类型判断 → 关键物料标记 → 任务触发 → 任务同步至供应商 → 状态更新
- 生产计划编制与审批流程：任务类型判断 → 计划编辑 → 计划校验 → 审批流程触发 → 审批结果处理 → 状态更新
- 进度反馈与数据回传流程：订单状态判断 → 反馈信息编辑 → 可编辑范围判断 → 状态更新与数据回传 → 采购端监控
- 异常预警与处理流程：预警触发类型判断 → 预警信息推送 → 差异化展示 → 预警处理 → 闭环规则执行 → 预警升级

#### 场景：业务逻辑实现
给定后端需求
当设计业务逻辑时
则：
- 订单生命周期管理：同步、标记、下发、接收、执行、完成、归档
- 计划生命周期管理：生成、校验、提交、审批、执行、闭环
- 预警生命周期管理：触发、提醒、处理、闭环
- 关键物料标记规则：按高价值、长周期、制造符合性检查项目等规则标记
- 任务下发规则：基于订单交货期-制造周期自动计算下发时间，或手动指定
- 计划校验规则：校验计划完成时间≤订单交货期、责任人不能为空、关键物料计划明细不可缺失、台份/型号ID与主数据一致
- 预警阈值规则：进度预警阈值（延迟≥3天）、反馈预警阈值（超24小时未提交），支持系统管理员自定义配置
- 数据回传规则：供应商提交反馈后，数据实时回传（延迟≤5分钟），且不可逆向修改（仅可补充备注）
- 权限生效规则：角色权限配置后即时生效，用户需重新登录刷新权限
- 制造符合性检查规则：标记为制造符合性检查的零部件，需额外反馈检查时间点，且检查完成后需上传检查报告附件

#### 场景：后端技术实现
给定后端需求
当设计技术实现时
则：
- 框架架构：基于 Nest.js 模块化架构，划分核心模块（订单模块、计划模块、权限模块、预警模块、数据分析模块），模块间通过服务调用解耦
- 数据库设计：核心表（采购订单表、采购订单明细表、生产计划表、反馈数据表、角色权限表、预警表）；表关联通过订单编号、物料图号、供应商 ID 建立；索引设计对订单编号、物料图号、任务状态、时间字段建立索引；分表策略对历史订单数据（超过 1 年）分表存储
- API 接口设计：遵循 RESTful 规范，接口路径按模块划分（如 /api/order、/api/plan、/api/warning），支持分页、排序、筛选参数；提供接口文档（基于 Swagger）
- 认证授权：使用 JWT 生成令牌，基于 RBAC 模型，结合数据级权限，在接口层拦截非授权访问
- 规则引擎：集成 Camunda 7.24 流程引擎，配置任务下发、计划审批、预警触发等流程，支持流程节点自定义（如审批人、触发条件）
- 定时任务：使用 Nest.js Schedule 模块，实现定时同步 ERP 数据（每小时）、定时检测预警规则（每分钟）、定时归档历史数据（每天凌晨）
- 日志系统：使用 winston 记录系统日志，区分操作日志（用户行为）、业务日志（订单/计划状态变更）、错误日志（接口异常、流程失败），日志支持按时间/模块/级别查询
- 数据同步：与 ERP 系统对接采用「定时同步 + 手动触发同步」双模式，同步失败时记录错误日志并推送提醒至系统管理员
- 性能优化：接口响应时间控制在 2 秒内，批量导入/导出采用异步处理（返回任务 ID，完成后推送通知）；数据库查询使用分页、索引、联表优化，避免全表扫描

### PD5: 集成设计

#### 场景：ERP 系统集成
给定集成需求
当设计 ERP 集成时
则：
- 集成方式：基于 ERP 系统提供的 API 接口，实现数据同步
- 同步内容：采购订单、采购订单明细、人员信息、供应商信息
- 同步频率：定时同步（每小时） + 手动触发同步
- 错误处理：同步失败时记录错误日志，并推送提醒至系统管理员
- 数据转换：将 ERP 系统数据转换为系统内部数据模型
- 变更检测：自动检测订单类型（新订单/变更订单），并做相应处理

#### 场景：Camunda 工作流集成
给定集成需求
当设计 Camunda 集成时
则：
- 工作流定义：采购任务下发流程、生产计划制定流程、生产计划变更调整流程、预警处理流程
- 集成方式：使用 Camunda 7.24 REST API 进行工作流管理
- 事件监听：实现工作流事件的事件监听器，及时响应工作流状态变更
- 流程配置：支持流程节点自定义（如审批人、触发条件）
- 日志记录：使用 winston 记录工作流操作日志

#### 场景：第三方系统集成
给定集成需求
当设计第三方系统集成时
则：
- 企业微信集成：适配企业微信公开接口，实现消息推送
- 邮箱集成：适配邮箱 SMTP 接口，实现邮件通知
- 集成范围：仅适配已有公开接口，不负责第三方系统的接口开发

### PD6: 用户角色与权限设计

#### 场景：角色定义与权限
给定权限需求
当设计角色与权限时
则：
- 系统管理员：全系统用户/角色/权限配置；系统参数（预警阈值、规则引擎）配置；数据备份/日志查看；所有模块操作权限
- 采购主管：采购订单查看/关键物料标记/任务下发；生产计划审批；所管任务进度监控；预警处理/订单关闭；报表导出
- 供应商负责人：本单位任务接收/确认；本单位生产计划审核（提交前）；本单位任务进度查看；本单位预警处理
- 供应商操作人员：被分配任务的生产计划编制/导入；进度反馈填报；个人待办任务处理；本岗位数据查看
- 公司/部门领导：全系统数据监控看板查看；订单/交付统计报表导出；异常预警汇总查看；无编辑/审批权限

#### 场景：权限控制规则
给定权限需求
当设计权限控制时
则：
- 数据级权限：基于「组织 + 任务 + 角色」三维管控，如供应商仅能查看本单位承接的任务，采购主管仅能查看所负责台份的任务
- 操作级权限：按任务状态控制，如未下发任务不可填报、已完成任务不可更改、审批中计划不可编辑
- 功能级权限：系统管理员可配置所有功能，普通角色仅开放授权范围内的菜单与按钮（如供应商无用户管理权限）
- 权限继承：高等级角色继承低等级角色权限（如公司领导可查看采购主管的所有数据，不可执行采购主管的审批操作）

### PD7: 全局规则与可追溯设计

#### 场景：全局统一规则
给定系统需求
当设计全局规则时
则：
- 最小化操作原则：所有变更流程均保留原订单/计划数据，仅解锁变更相关项，避免重复操作
- 双向实时同步原则：采购端的变更操作、供应商端的变更处理进度，双方数据实时同步，无信息差
- 差异化提醒原则：所有变更相关任务、待办、预警均以红色标签/高亮展示，与正常流程明确区分
- 全操作留痕原则：系统对所有变更相关操作自动记录，包括操作人、操作时间、操作内容、前后数据对比，记录不可删除、不可修改

#### 场景：全流程追溯设计
给定系统需求
当设计可追溯性时
则：
- 变更记录时间轴：所有订单/计划的详情页，均嵌入「变更记录时间轴」（按时间倒序展示），整合采购端+供应商端的所有变更操作记录，支持查看、截图、Excel 导出
- 订单变更统计报表：系统在「数据监控与闭环分析模块」新增「订单变更统计报表」，支持按时间、供应商、变更类型、变更处理效率等维度统计，包括待发起变更条目数、已发起变更条目数、各订单变更次数及变更原因统计
- 永久关联归档：所有变更记录与原订单/计划数据永久关联归档，可通过订单编号、物料图号、任务编号多维度检索

### PD8: 性能与安全设计

#### 场景：性能要求
给定系统需求
当设计性能时
则：
- 并发能力：支持 100+ 用户同时在线操作，核心接口（如反馈提交、订单查询）支持 50+ 并发请求
- 响应时间：页面加载时间 < 2 秒，接口响应时间 < 2 秒（批量导入/导出等异步操作除外）
- 数据存储：支持至少 3 年的订单/计划/反馈数据存储，历史数据可归档至离线库
- 可用性：系统全年可用率≥99.9%，故障恢复时间≤1 小时

#### 场景：安全性要求
给定系统需求
当设计安全性时
则：
- 数据加密：用户密码加盐哈希存储，敏感数据（如供应商联系方式、物料价格）传输与存储加密
- 访问控制：支持 IP 白名单、登录失败次数限制（连续 5 次失败锁定账号 1 小时）
- 审计日志：记录所有敏感操作（权限变更、订单下发、预警处理），日志不可篡改
- 接口安全：API 接口支持签名验证，防止非法调用；跨域请求仅允许指定域名访问

## 项目边界与范围

### 场景：项目边界
给定系统开发
当系统实现时
则系统应：
- 不涉及 ERP 系统的功能修改，仅通过 API 调用获取数据；
- 不涉及供应商现场生产设备的数据采集（仅接收供应商手动/Excel 导入的反馈数据）；
- 不提供移动端 APP 开发，仅支持移动端浏览器访问适配页面；
- 不包含制造符合性检查的具体业务逻辑（仅标记、存储相关数据，不参与检查流程）；
- 不负责第三方系统（如企业微信、邮箱）的业务逻辑，仅适配已有公开接口。

### 场景：系统通知与消息推送
给定系统需求
当设计通知功能时
则系统应：
- 站内信通知：系统内部消息中心，展示各类通知（预警、审批、任务），支持标记已读、删除、筛选；
- 邮件通知：适配邮箱 SMTP 接口，实现预警、审批、任务等重要通知的邮件推送；
- 企业微信通知：适配企业微信公开接口，实现预警、审批、任务等重要通知的企业微信推送；
- 通知模板：支持自定义通知模板，包括通知标题、内容、链接等；
- 通知记录：所有通知发送记录可查询，包括发送时间、接收人、发送状态等。
