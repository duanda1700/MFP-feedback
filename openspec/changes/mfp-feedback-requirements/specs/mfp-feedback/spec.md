# MFP-Feedback 系统规范

## 新增需求

### FR1: 采购订单下达与任务分发

#### 描述
系统应基于 ERP 数据自动生成制造任务并分发给供应商，实现任务精准、自动、可视分发。

#### 场景：承制订单视图
给定采购订单数据
当采购主管查看订单时
则系统应：
- 集成 ERP 采购订单、人员信息、供应商信息主数据
- 按供应商维度展示承接任务清单（含状态：待接收/已接收/执行中/已完成）
- 支持订单明细穿透式查看（物料图号、数量、交货期、合同编号）

#### 场景：承制订单查询与筛选
给定用户需要查找特定订单
当用户执行查询操作时
则系统应：
- 支持多维度组合查询：订单编号、物料图号、名称、数量、交货日期、状态等
- 支持模糊搜索、下拉选择、条件组合、导出报表

#### 场景：关键物料标记管理
给定采购订单明细
当用户需要标记关键物料时
则系统应：
- 提供前端配置页面，支持对采购订单明细中的物料进行“关键件”标识
- 标记后自动同步至供应商任务清单，作为分解工序级计划管控执行项
- 支持按规则标记（高价值、长周期、制造符合性检查项目等，支持扩展）

#### 场景：任务自动下发
给定采购订单数据
当系统处理订单时
则系统应：
- 基于规则引擎自动触发任务下发
- 以采购主管账号自动触发采购任务下发流程
- 支持手动触发任务下发

### FR2: 研制任务进展反馈

#### 描述
系统应允许供应商更新制造进度并实时跟踪任务状态，构建“计划-执行-反馈”闭环。

#### 场景：生产计划视图
给定生产计划数据
当用户查看生产计划时
则系统应：
- 列表展示所有任务（含任务名称、责任单位、计划开始、交付时间、关键物料标记）
- 支持按任务类型、单位、时间范围、关键件等筛选
- 可视化百分比展示整体完成率

#### 场景：生产计划编排
给定生产计划数据
当用户编制生产计划时
则系统应：
- 支持基于承制订单明细自动生成生产计划（增加责任人、计划完成时间、计划状态、备注等信息）
- 支持标准模板下载(excel),支持本地编辑后上传

#### 场景：计划导入与校验
给定用户需要导入生产计划
当用户执行导入操作时
则系统应：
- 支持批量导入 EXCEL 文件
- 自动校验格式、逻辑一致性（如：任务缺失）
- 导入成功后更新计划视图，如失败则提示详细原因
- 导入成功后触发“生产计划制定流程”，由采购主管审批

#### 场景：进度反馈
给定生产计划数据
当供应商提交进度反馈时
则系统应：
- 提供同屏双列表，左侧为承制订单、右侧为此订单下属计划明细反馈表
- 每个承制订单对应一个反馈表单，包含：计划编号、项目号、台份/型号有效性ID、零组件件号、零组件名称、数量、任务书编号、外采/自制状态、计划开始时间、计划结束时间、责任人、计划状态、备注、关键零部件标记、制造符合性检查零部件标记、制造符合性检查时间点
- 责任人、计划状态、备注为可编辑信息

#### 场景：反馈数据自动回传与状态更新
给定供应商提交的进度反馈
当系统处理反馈数据时
则系统应：
- 自动更新任务状态
- 回传数据可被“数据监控与闭环分析”模块实时监控
- 供人员实时查看，形成“执行反馈闭环”

### FR3: 人员权限与组织管理

#### 描述
系统应实现具有不同权限级别的基于角色的访问控制，支撑全系统安全可控运行，实现“谁可看、谁可操作、谁可审批”。

#### 场景：角色定义
给定系统用户
当系统分配角色时
则系统应：
- 定义系统管理员（全局权限）
- 定义采购主管（采购订单发生变更时创建/修改采购任务；审批供应商制定的“生产计划制定流程”；监控所管台份、单元体的制造交付情况）
- 定义供应商负责人（查看本单位任务、填报进度）
- 定义供应商操作人员（查看被分配任务、填报反馈）
- 定义公司/部门领导（查看全系统数据监控看板、导出报表、查看异常预警汇总）

#### 场景：权限粒度控制
给定系统用户
当系统控制权限时
则系统应：
- 按组织层次控制数据可见范围（公司领导、采购与供应链管理部领导可查看全部数据；采购主管可查看所负责台份、专业数据；供应商负责人可查看本单位数据、供应商操作人员可查看所负责数据）
- 按任务状态控制操作权限：未下发任务不可填报，已完成任务不可更改
- 支持“数据级权限”

### FR4: 个人与供应商代办

#### 描述
系统应提供个人与供应商代办中心，展示待处理任务并支持一键跳转至对应操作流程。

#### 场景：个人代办中心
给定系统用户
当用户查看个人代办中心时
则系统应：
- 展示个人名下所有待处理任务，包括：新任务/变更任务接收提醒、计划编制待提交、进度反馈待填报、审批待处理
- 支持一键跳转至对应操作流程

#### 场景：供应商待办中心
给定供应商用户
当用户查看供应商待办中心时
则系统应：
- 仅展示分配给该供应商的任务：包括：任务接收确认、计划编制提交、进度反馈填报
- 提供清晰的代办事项列表、与优先级标识（关键零部件、制造符合性检查零部件标红）

#### 场景：流程状态可视
给定系统任务
当用户查看任务时
则系统应：
- 在待办页面显示当前流程节点
- 提供流程状态的可视化展示

### FR5: 数据监控与闭环分析

#### 描述
系统应提供数据监控与闭环分析功能，支撑决策与持续优化，体现“闭环机制”的价值。

#### 场景：任务执行看板
给定系统数据
当用户查看任务执行看板时
则系统应：
- 按时间/供应商/台份/物料类型多维度统计核心指标
- 展示订单条目统计：累计下发条目数、已完成条目数、执行中条目数、未开始条目数（含占比可视化）
- 展示订单变更统计：待发起变更条目数、已发起变更条目数、各订单变更次数及变更原因统计
- 展示承制单位交付统计：各单位承接条目数、完成条目数、准时交付率/延期交付率、平均交付周期

#### 场景：异常预警
给定系统数据
当系统检测到异常时
则系统应：
- 提供阈值自定义配置
- 进度预警：计划完成时间延迟≥3天的任务，标红预警，关联对应采购主管与承制单位负责人
- 反馈预警：超过24小时未提交进度反馈的任务，标黄预警，自动推送提醒至供应商操作人员
- 预警信息同步至待办中心 + 站内信提醒

#### 场景：预警处理
给定预警任务
当用户处理预警时
则系统应：
- 支持预警任务一键跳转至处理页面
- 记录预警处理结果与闭环时间

### FR6: 页面设计与交互流程

#### 描述
系统应提供直观、易用的用户界面，支持全系统统一基础布局规范和核心交互流程。

#### 场景：全系统统一基础布局
给定系统界面
当用户使用系统时
则系统应：
- 采用「顶部导航栏 + 左侧侧边栏 + 主内容区 + 底部信息栏」的经典布局
- 统一配色体系（主色调：工业蓝 #1E88E5，辅助色：警示红 #FF5252、成功绿 #4CAF50，中性色：深灰 #333333、浅灰 #EEEEEE）
- 统一字体（正文：微软雅黑 / Inter，14px；标题：微软雅黑 / Inter Bold，16-24px）
- 统一组件样式（按钮、输入框、表格、弹窗等）

#### 场景：核心交互流程
给定系统操作
当用户执行操作时
则系统应：
- 支持采购订单下达与任务分发流程
- 支持生产计划编制与审批流程
- 支持进度反馈与数据回传流程
- 支持异常预警与处理流程
- 遵循最小化操作原则、双向实时同步原则、差异化提醒原则、全操作留痕原则

#### 场景：详细页面列表
给定系统界面
当用户使用系统时
则系统应：
- 登录页：用户登录系统，支持账号密码登录、验证码登录，包含忘记密码、记住密码功能
- 仪表盘（首页）：展示系统核心统计指标、异常预警、待办任务汇总、关键物料进度可视化图表
- 采购订单管理页：展示 ERP 同步的采购订单列表，支持订单查询、筛选、关键物料标记、任务下发操作
- 承制订单详情页：穿透式查看订单明细（物料图号、数量、交货期等），展示订单全生命周期状态
- 生产计划编制页：在线编辑 / 导入生产计划，支持计划校验、提交审批，展示计划编制进度
- 进度反馈填报页：双列表展示承制订单与计划明细，支持责任人、状态、备注等信息编辑与提交
- 个人代办中心页：展示用户名下待处理任务，支持筛选、一键跳转操作、流程节点可视化
- 供应商代办中心页：展示供应商待处理任务，关键件 / 制造符合性检查任务标红，支持优先级筛选
- 角色权限配置页：管理系统角色定义、权限粒度配置、数据级权限分配
- 系统设置页：配置阈值（进度预警、反馈预警）、规则引擎（任务自动下发规则）、系统参数
- 数据监控看板页：多维度展示订单统计、交付统计、异常预警，支持自定义时间范围与报表导出
- 预警处理页：处理预警任务，记录处理结果与闭环时间，关联采购主管与供应商负责人

#### 场景：全流程追溯要求
给定系统任务
当用户查看任务时
则系统应：
- 所有订单 / 计划的详情页，均嵌入「变更记录时间轴」（按时间倒序展示），整合采购端 + 供应商端的所有变更操作记录，支持查看、截图、Excel 导出
- 系统在「数据监控与闭环分析模块」新增「订单变更统计报表」，支持按时间、供应商、变更类型、变更处理效率等维度统计
- 所有变更记录与原订单 / 计划数据永久关联归档，可通过订单编号、物料图号、任务编号多维度检索

### FR7: 业务逻辑与技术实现

#### 描述
系统应实现完整的业务逻辑和技术架构，支持核心业务生命周期和关键业务规则。

#### 场景：核心业务生命周期
给定系统业务
当系统处理业务时
则系统应：
- 支持采购订单生命周期：同步 → 标记 → 下发 → 接收 → 执行 → 完成 → 归档
- 支持生产计划生命周期：生成 → 校验 → 提交 → 审批 → 执行 → 闭环
- 支持预警生命周期：触发 → 提醒 → 处理 → 闭环

#### 场景：关键业务规则
给定系统业务
当系统处理业务时
则系统应：
- 关键物料标记规则：支持按「高价值（单价≥XX 元）、长周期（制造周期≥XX 天）、制造符合性检查项目」等规则标记
- 任务下发规则：基于「订单交货期 - 制造周期」自动计算下发时间，或采购主管手动指定
- 计划校验规则：校验计划完成时间≤订单交货期、责任人不能为空、关键物料计划明细不可缺失、台份 / 型号 ID 与主数据一致
- 预警阈值规则：进度预警阈值（延迟≥3 天）、反馈预警阈值（超 24 小时未提交）支持系统管理员自定义配置
- 数据回传规则：供应商提交反馈后，数据实时回传（延迟≤5 分钟），且不可逆向修改（仅可补充备注）
- 权限生效规则：角色权限配置后即时生效，用户需重新登录刷新权限
- 制造符合性检查规则：标记为制造符合性检查的零部件，需额外反馈检查时间点，且检查完成后需上传检查报告附件

#### 场景：技术实现
给定系统架构
当系统实现时
则系统应：
- 前端：Vue 3 + TypeScript + Vue-Vben-Admin
- 后端：Nest.js + TypeScript
- 数据库：MySQL 8.0
- 流程引擎：Camunda 7.24
- 支持与 ERP 系统集成
- 支持与 Camunda 工作流引擎集成

#### 场景：前端实现要点
给定前端开发
当系统实现时
则系统应：
- 框架复用：基于 Vue-Vben-Admin 开箱即用的组件，减少重复开发
- 状态管理：使用 Pinia 管理全局状态，按模块划分 store
- API 请求：封装 Axios 请求拦截器，统一处理 JWT 令牌校验、请求头设置、错误捕获
- 表单验证：基于 VeeValidate / Element Plus 表单验证规则，封装通用验证方法
- 数据可视化：集成 ECharts 实现仪表盘、订单统计、交付率、预警趋势等图表
- 文件处理：使用 xlsx 库处理 Excel 导入 / 导出，支持批量导入时的错误详情导出
- 响应式适配：基于 Vue-Vben-Admin 的适配方案，支持 PC 端不同分辨率
- 缓存策略：本地缓存用户权限、常用筛选条件、最近访问页面，减少接口请求

#### 场景：后端实现要点
给定后端开发
当系统实现时
则系统应：
- 框架架构：基于 Nest.js 模块化架构，划分核心模块，模块间通过服务调用解耦
- 数据库设计：设计核心表（采购订单表、采购订单明细表、生产计划表、反馈数据表、角色权限表、预警表）
- API 接口设计：遵循 RESTful 规范，接口路径按模块划分，支持分页、排序、筛选参数
- 认证授权：使用 JWT 生成令牌，基于 RBAC 模型，结合数据级权限，在接口层拦截非授权访问
- 规则引擎：集成 Camunda 7.24 流程引擎，配置任务下发、计划审批、预警触发等流程
- 定时任务：使用 Nest.js Schedule 模块，实现定时同步 ERP 数据、定时检测预警规则、定时归档历史数据
- 日志系统：使用 winston 记录系统日志，区分操作日志、业务日志、错误日志
- 数据同步：与 ERP 系统对接采用「定时同步 + 手动触发同步」双模式
- 性能优化：接口响应时间控制在 2 秒内，批量导入 / 导出采用异步处理

#### 场景：数据库设计
给定数据库开发
当系统实现时
则系统应：
- 采购订单表（PURCHASE_ORDER）：包含 ID、BPM_CGDD_ID、BPM_CGDD_INSTANCE_ID、DJBH、APPLY_USERNAME、APPLY_USERNO、APPLY_DEPT、BUDGET_NO、SECOND_PLAN_NAME、PURCHASE_LEVEL、ACTUAL_PLAN_PURCHASE_NAME、IS_TEMPORARY_EMERGENCY、PURCHASE_TASK_TYPE、MAJOR、PROJECT、VERSION、VERSION_CONTROL_TYPE、ORDER_STATUS、SET_COUNT、SUPPLIER_CODE、SUPPLIER_NAME、PURCHASE_MANAGER、CREATE_TIME、UPDATE_TIME
- 采购明细表（PURCHASE_DETAILS）：包含 ID、BPM_CGDDMX_ID、BPM_CGDD_INSTANCE_ID、RECEIVE_COMPANY、MATERIAL_CODE、MATERIAL_DESC、MATERIAL_GROUP、QUANTITY、PLAN_DATE、UNIT、PLAN_NO、PRODUCT_TYPE、SECOND_PLAN_NO、ORDER_NO、SET_COUNT、DRAWING_NO、CHANGE_TYPE、SUPPLIER_CODE、DELIVERY_DATE、PURCHASE_MANAGER、DETAIL_STATUS、CREATE_TIME、UPDATE_TIME、IS_KEY_MATERIAL、IS_CONFORMITY_CHECK
- 生产计划表（PRODUCTION_PLAN）：包含 ID、PURCHASE_DETAILS_ID、PLAN_START_TIME、PLAN_END_TIME、RESPONSIBLE_PERSON、PLAN_STATUS、NOTE、VERSION、CREATE_TIME、UPDATE_TIME

### FR8: 项目范围与边界

#### 描述
系统应明确项目范围与边界，包括核心功能、辅助功能、非功能范围和项目边界。

#### 场景：功能范围
给定系统开发
当系统实现时
则系统应：
- 核心功能（必须实现）：采购订单同步、关键物料标记、任务自动 / 手动下发；生产计划编制（在线编辑 / Excel 导入）、校验、审批；进度反馈填报、数据实时回传、任务状态更新；角色权限配置（数据级 / 操作级权限）；个人 / 供应商代办中心（待办提醒、一键跳转）；数据监控看板（多维度统计、可视化）；异常预警（阈值配置、提醒、处理、闭环）；报表导出（订单、计划、交付、预警数据）
- 辅助功能（建议实现）：系统通知（站内信、待办提醒）；操作日志查询（用户行为、数据变更）；模板管理（Excel 导入 / 导出模板自定义）；消息推送（预警、审批、任务下发推送至邮箱 / 企业微信）；历史数据归档与查询

#### 场景：非功能范围
给定系统开发
当系统实现时
则系统应：
